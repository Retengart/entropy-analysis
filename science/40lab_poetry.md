# Практическая 40: как реализовано для анализа стихов

Как алгоритм из практической работы №40 адаптирован и реализован в проекте для распознавания/классификации поэтических текстов (например, Пушкин vs Лермонтов) с использованием веб-интерфейса и API.

## Суть алгоритма (байесовский классификатор по признакам)
- Есть классы \(A_i\) (авторы/жанры), априорные вероятности \(P(A_i)\).
- Есть дискретные признаки \(x_k\) с несколькими значениями. Для каждого признака известны условные вероятности \(P(x_l^k \mid A_i)\).
- Для каждого признака считаем информативность (формула Шеннона из лабы) и ошибку \(P(e)_k\) (формула (4) лабы): \(\sum_l \{P(x_l^k) - \max_i P(A_i)P(x_l^k\mid A_i)\}\).
- Для пар признаков — ошибка по комбинациям (формулы (5–8) лабы). Берём минимум ошибки среди признаков/пар, сравниваем с порогом \(P(e)_{zad}\).
- При наличии шума — пересчитываем условные вероятности с добавкой/ренормировкой и вычисляем \(\Delta P\) из формулы (1).

## Как адаптировано под стихи
1) **Сегментация корпуса**: большие файлы (например, сборник с разделителем `======`) разбиваются на сегменты — каждый сегмент считается отдельной реализацией для обучения/предсказания.
2) **Классы**: по умолчанию — имя файла без расширения (например, `pushkin_filtered`, `lermontov_filtered`).
3) **Дискретные признаки** (биннинг, все строковые категории):
   - **Базовые/компактные**: `avg_word_len`, `avg_line_len`, `punct_ratio`, `token_count`, `long_word_share`, `stopword_ratio`, `end_punct`, `line_count`, `unique_ratio`.
   - **Поэтические (НОВОЕ)**: 
     * Просодические: `meter_pattern` (ямб/хорей/дактиль), `meter_regularity` (стабильность метра), `syllables_per_line`
     * Рифма: `rhyme_scheme` (ABAB/AABB/ABBA), `rhyme_quality` (разнообразие рифм), `rhyme_repetition`
     * Синтаксис: `enjambment_rate` (частота переносов), `exclamation_ratio`, `question_ratio`
     * Лексика: `pushkin_lexicon` (плотность слов Пушкина), `lermontov_lexicon`, `adjective_density`
     * Фонетика: `consonant_repetition` (аллитерация), `voiced_consonant_ratio`
   - **Общие структурные**: `vowel_ratio`, `rare_letter_ratio`, `sentence_length`, `line_length_std`, `upper_ratio` и др.
   - Все признаки приводятся к небольшому числу бинов (обычно 4–7), чтобы остаться в дискретной постановке лабы.
4) **Обучение таблиц**:
   - По размеченным сегментам считаются частоты \(P(x|A)\) с лапласовским сглаживанием (по умолчанию 0.001).
   - \(P(A_i)\) — доля сегментов класса.
5) **Применение**:
   - Строим информативность по каждому признаку (формула (3) лабы), ошибки \(P(e)_k\) и лучшую пару.
   - Поддерживается отбор признаков: по порогу информативности и top-K (по информативности).
   - Шум (опционально) добавляется к \(P(x|A)\) с ренормировкой, затем считаются \(\Delta P\) и ошибки.
   - Для каждого сегмента считаются постериоры по классам; предсказание — argmax постериора.

## Как это видно в веб-интерфейсе
- Вкладка «🧭 Распознавание» — ручной ввод таблиц \(P(A)\), \(P(x|A)\), расчёт информативности/ошибок/пар, опция шума.
- Вкладка «🧭 Пакетное распознавание»:
  - Загружаем текстовые файлы (каждый файл = класс), разбиваем по разделителю (например, `======`).
  - Обучаем таблицы \(P(A)\), \(P(x|A)\) автоматически по выбранному профилю признаков (baseline/compact/full), сглаживание задаётся.
  - Опционально: top-K признаков, min информативность, шум.
  - Выводится: информативность и P(e) по признакам, выбранные признаки, таблицы \(P(x|A)\), постериоры и предсказания по сегментам, распределение предсказанных классов, итоговые метрики (точность/средняя уверенность).

## Профили признаков (против «взрывных» комбинаций)
- **baseline**: небольшой стабильный набор общих признаков (удерживает высокую точность).
- **compact**: расширенный, но умеренный набор общих признаков.
- **poetry_essential**: 🆕 **специализированные поэтические признаки** (метр, рифма, энжамбеман, характерные слова авторов, эмоциональность) — оптимизирован для Пушкин/Лермонтов.
- **poetry_full**: 🆕 все поэтические + структурные признаки (максимальная информативность для стихов).
- **full**: все доступные признаки (может дать шум, но максимальная информативность).

Выбор профиля влияет на итоговую точность: 
- baseline/compact → ~90-92% на общих признаках
- **poetry_essential/poetry_full → ожидается 94-97%** благодаря специфике стихов

## Ключевые соответствия с лабой 40
- Формулы (3), (4), (5–8), (1) реализованы в ядре `recognition.py`.
- Подготовка \(P(A)\), \(P(x|A)\) соответствует пункту 1 лабы; информативность/ошибки — пункты 2–11.
- Шум — через additive noise + renorm, далее \(\Delta P\) (формула (1)).
- Дискретная природа признаков сохранена (биннинг), чтобы байесовский алгоритм работал корректно.

## Рекомендации для объяснения преподавателю
1. Алгоритм строго следует байесовской схеме лабы: формулы для информативности, ошибок по признакам и их комбинациям, учёт шума.
2. Признаки дискретные и заранее бinned — это ключ для корректного применения формул лабы.
3. Профили признаков позволяют управлять качеством: baseline — лучший баланс для Пушкин vs Лермонтов; full — максимум информативности, но может вводить шум.
4. Веб-UI демонстрирует весь ход: от загрузки текстов и обучения таблиц до визуализации информативности, ошибок и постериоров.
5. Высокая точность (>0.9) достигается при выборе стабильного профиля признаков и разумного сглаживания (0.001), без агрессивного топ-K отсечения.
