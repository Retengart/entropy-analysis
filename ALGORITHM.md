## Энтропийный анализ поэтических текстов по начальной букве

Этот документ описывает алгоритм, который вычисляет распределение начальных букв слов стихотворения, информационную энтропию этого распределения, а также дополнительные статистики (математическое ожидание и стандартное отклонение ранга букв). Документ также фиксирует правила нормализации текста, формат выходных данных, требования к визуализации и предлагаемый набор библиотек для реализации на Rust.

### Теоретическая основа

- Пусть N — число слов в тексте (после нормализации и фильтрации).
- Пусть n_i — число слов, начинающихся на i-ую букву выбранного алфавита.
- Тогда p_i = n_i / N — эмпирическая частота появления i-ой начальной буквы.
- Информационная энтропия распределения начальных букв:

\[ H = -\sum_i p_i\,\log_2 p_i \]

- Для дальнейшего сравнения текстов вводим ранги букв r_i (позиция в алфавите, начиная с 1) и вычисляем:
  - математическое ожидание ранга: \( \bar{x} = \sum_i r_i\, p_i \)
  - стандартное отклонение: \( \sigma = \sqrt{\sum_i (r_i - \bar{x})^2\, p_i} \)

Эти формулы соответствуют методике из учебно-практических материалов, где исходно расчёты выполнялись в Word/Excel с заменой пробелов на переводы строк, подсчётом частот и построением гистограмм.

### Алфавит и нормализация

По умолчанию используем «учебный» русский алфавит из 28 букв, как в методичке (без «ё», «й», «ъ», «ь»):

а б в г д е ж з и к л м н о п р с т у ф х ц ч ш щ э ю я

Порядок букв определяет их ранг r_i = 1..28. Для воспроизводимости вычислений важно зафиксировать правила нормализации:

1) Приведение к нижнему регистру (Unicode case folding).
2) Замены для соответствия 28-буквенному алфавиту:
   - «ё» → «е» (по умолчанию)
   - «й» → «и» (по умолчанию)
   - начальные «ъ», «ь» игнорируются (такие слова исключаются из подсчёта)
3) Токенизация: слово — максимальная последовательность букв кириллицы [а-яёА-ЯЁ]. Все иные символы (знаки препинания, цифры, кавычки, тире, дефисы, эм-деши и т. п.) считаются разделителями.
4) Для сложных случаев:
   - Сложные/дефисные формы («как-то», «из-за», «с-под») разбиваются на отдельные подслова; учитывается начальная буква каждого подслова.
   - Если токен начинается с некириллической буквы — токен игнорируется.
5) Конфигурируемость:
   - Режим «rus33» — полноразмерный алфавит из 33 букв с отдельными «ё» и «й», а также «ъ», «ь». В этом режиме не выполняются замены из п.2, а «ъ», «ь» включаются в алфавит и ранжируются.
   - Режим «custom» — алфавит задаётся пользователем явным списком символов и порядком.

Итог подсчёта производится только по словам, удовлетворяющим выбранному режиму нормализации. Число таких слов и есть N.

### Пошаговый алгоритм (один текст)

1) Чтение исходного текста в UTF‑8.
2) Нормализация согласно правилам выше.
3) Токенизация и извлечение начальных букв каждого слова/подслова.
4) Подсчёт n_i по фиксированному алфавиту; одновременное накопление N.
5) Расчёт частот p_i = n_i / N. Для отсутствующих букв p_i = 0.
6) Расчёт энтропии H в битах: \( H = -\sum_i p_i\log_2 p_i \) (принять 0·log2(0) = 0).
7) Расчёт \(\bar{x}\) и \(\sigma\) по формулам выше (используя ранги выбранного алфавита).
8) Формирование отчётов:
   - Таблица по буквам: rank, letter, count, p_i, p_i·log2(p_i).
   - Итоговые метрики: N, H, \(\bar{x}\), \(\sigma\), число ненулевых букв K_nz.
   - Визуализации: гистограмма p_i по алфавиту; гистограмма p_i, отсортированная по возрастанию.

### Пакетный режим (много текстов)

Для набора файлов (напр., все стихи автора) алгоритм применяется к каждому тексту, после чего формируется сводная таблица: file, N, H, x_mean, sigma. На этой основе можно:

- Строить диаграммы распределения H.
- Исследовать корреляцию между H и N (коэффициент Пирсона r).

### Форматы вывода

- Консоль: краткий текстовый отчёт по одному тексту.
- CSV: построчная таблица по буквам; отдельный итоговый CSV по текстам в пакетном режиме.
- JSON: метрики и распределение p_i с метаданными (алфавит, режим нормализации, версия ПО).
- Графика: PNG и/или SVG гистограмм.

### Числовая стабильность и погрешности

- Для H использовать f64, логарифм по основанию 2 через `ln`/`log2` ядра.
- В суммах типов \(\sum p_i \log_2 p_i\), \(\sum r_i p_i\) и \(\sum (r_i - \bar{x})^2 p_i\) использовать аккуратный порядок/компенсированное суммирование при необходимости; в масштабе задачи стандартного f64 достаточно.

### Предлагаемые библиотеки

- clap — CLI парсинг, автогенерация справки, профили и подкоманды. [`docs.rs/clap`](https://docs.rs/clap/latest/clap/)
- regex — выделение слов по шаблону `(?iu)[а-яё]+`.
- unicode-segmentation (опционально) — работа с графемами при необходимости.
- serde + serde_json, csv — сериализация отчётов.
- plotters — построение PNG/SVG гистограмм. Требования к Linux: `pkg-config`, `libfreetype6-dev`, `libfontconfig1-dev`. См. документацию: [Plotters 0.3.x](https://docs.rs/plotters/latest/plotters/).
- polars (опционально для пакетного режима) — сводные таблицы, корреляция, экспорт в Parquet/CSV. [`docs.rs/polars`](https://docs.rs/polars/0.51.0/polars/)
- anyhow/thiserror — удобная обработка ошибок.
- walkdir, rayon (опционально) — рекурсивный обход каталогов и параллельная обработка многих файлов.

Рекомендуемые фичи Plotters: `bitmap` и/или `svg` backends. На сервере без GUI использовать SVG/bitmap backend’ы.

### Предлагаемый CLI (черновик)

```
entropy-analysis analyze <PATH | -> \
  [--alphabet rus28|rus33|custom] \
  [--custom-alphabet "абв…"] \
  [--keep-yo] [--keep-j] \
  [--min-token-len 1] \
  [--csv out.csv] [--json out.json] \
  [--hist-alpha hist-alpha.png] [--hist-sorted hist-sorted.png] \
  [--svg]

entropy-analysis batch <DIR> \
  [--glob "**/*.txt"] [--recurse] \
  [--summary-csv summary.csv] [--summary-json summary.json] \
  [--corr] [--plots]
```

Пояснения:

- `--alphabet` выбирает 28/33/пользовательский режим. В `rus28` по умолчанию выполняются замены «ё»→«е», «й»→«и»; флаги `--keep-yo`, `--keep-j` их отключают.
- `--hist-alpha` — гистограмма p_i в порядке алфавита; `--hist-sorted` — по возрастанию p_i.
- В пакетном режиме дополнительно выводятся таблицы по файлам (N, H, x_mean, sigma) и, если указан `--corr`, коэффициент корреляции r(H, N).

### Структура данных и отчётов

1) По буквам (один текст):

| rank | letter | count | p_i | p_i_log2 | Remarks |
|-----:|:------:|------:|----:|---------:|:----|
|   1  |   а    |   n₁  | p₁  | p₁·log₂p₁ | ... |

2) Итог по тексту: `{ N, H_bits, x_mean, sigma, non_zero_letters, alphabet, normalization }`.

3) Пакетный итог: по одной строке на текст со столбцами `file, N, H_bits, x_mean, sigma`.

### Проверяемость и воспроизводимость

- В `--json` сохраняются исходные параметры нормализации и алфавит.
- Для одного и того же входа и параметров результат детерминирован.
- Юнит-тесты: (а) известные игрушечные тексты с ручными подсчётами; (б) проверка, что сумма p_i = 1 (с учётом машинной точности); (в) устойчивость к пустым/почти пустым входам.

### Ограничения и крайние случаи

- Пустой текст или отсутствие слов: N = 0 → H не определена. В отчёте возвращаем N=0 и H=null, x_mean=null, sigma=null.
- Обилие некириллических символов: по умолчанию игнорируются; при необходимости можно добавить `--allow-latin` и смешанные режимы, но это выходит за рамки методики.

### Наглядные результаты (ожидаемые)

- Для «Берёзы» Н. Рубцова методичка приводит близкие значения H и σ; программа должна воспроизвести их при режиме `rus28` и включённых заменах «ё»→«е», «й»→«и».

### План реализации (кратко)

1) Модуль нормализации и токенизации (regex, правила алфавита).
2) Подсчёт n_i, N; расчёт p_i, H, x_mean, σ.
3) Форматы вывода (CSV/JSON) и отрисовка гистограмм (plotters: PNG/SVG).
4) Пакетный режим и (опционально) сводная аналитика на Polars.
