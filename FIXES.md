# Исправления и улучшения

## Найденные проблемы

### 0. ⚖️ **ГЛАВНАЯ ПРОБЛЕМА: Дисбаланс данных**

**Математика:**
```
Пушкин:     442 сегмента × 1398 символов = 617,796 символов (2.3x больше!)
Лермонтов:  365 сегмента × 736 символов  = 268,640 символов
```

**Последствия:**
1. Байесовский классификатор склоняется к Пушкину (P(Pushkin) = 54.8%)
2. TF-IDF выдаёт мусор для Лермонтова (18 слов вместо 50)
3. Точность занижена на 5-10%

**Исправлено:**
- ✅ Балансировка приоров P(A) = 1/M (равномерное)
- ✅ Балансировка TF-IDF (одинаковое количество текстов)
- ✅ Фильтрация мусорных слов

### 1. ❌ Критическая ошибка: замыкание в цикле

**Проблема**: Все лексиконы использовали последнего автора из цикла.

```python
# БЫЛО (НЕПРАВИЛЬНО):
for author in authors:
    def make_extractor(author_name):
        return lambda text: bin_author_lexicon_density(text, author_name)
    feats.append(DiscreteFeature(..., extractor=make_extractor(author)))

# Все экстракторы получали ПОСЛЕДНЕГО автора!
```

**Исправлено**:
```python
for author in authors:
    def make_extractor(author_name=author):  # default argument
        return lambda text: bin_author_lexicon_density(text, author_name)
    feats.append(DiscreteFeature(..., extractor=make_extractor()))
```

### 2. 🗑️ Признаки с нулевой информативностью

**Проблема**: Использовались ВСЕ признаки, даже те, что не помогают (I=0.00000009).

**Исправлено**: Автоматически отбрасываем признаки с I < 1e-6.

### 3. 📊 TF-IDF не работал на малых данных

**Было**:
```python
min_df=2  # требовало минимум 2 вхождения
```

**Стало**:
```python
min_df=1          # даже редкие слова важны в поэзии
max_df=0.95       # убираем частые стоп-слова
sublinear_tf=True # логарифмическое масштабирование
```

### 4. 🔍 Нет диагностики

Добавлен скрипт `diagnose.py` для анализа проблем.

## Почему точность низкая (69%)?

### Возможные причины:

#### 1. **Слишком много авторов или они похожи**
Если Рубцов пишет похоже на Пушкина/Лермонтова — точность упадёт.

#### 2. **Мало данных**
Нужно минимум **50+ сегментов на автора** для хорошей точности.

#### 3. **Признаки не подходят**
Информативность всех признаков ~0.02-0.04 → они плохо различают авторов.

#### 4. **Качество текстов**
OCR-ошибки, опечатки, разметка могут мешать.

## Как диагностировать

### Запустите диагностику:
```bash
python diagnose.py
```

Покажет:
- Сколько сегментов у каждого автора
- Какой профиль лучше
- Какие признаки работают
- Где происходят ошибки

### Смотрите на:

1. **Информативность топ-признака**:
   - I > 0.5 → отлично
   - I = 0.1-0.5 → хорошо
   - I < 0.1 → плохо (авторы похожи или мало данных)

2. **Количество данных**:
   - < 30 сегментов на автора → мало
   - 30-100 → нормально
   - > 100 → хорошо

3. **Паттерны ошибок**:
   - Один автор путается с другим → они похожи
   - Все путаются → признаки не работают

3. **Попробуйте разные профили**:

4. **Используйте только сильные признаки**:
   - В веб-UI: "Мин. информативность" = 0.05
   - Или "Топ-K признаков" = 5

5. **Проверьте лексиконы**:
   - Смотрите вывод "📚 автор: характерных слов"
   - Должны быть осмысленные слова, не мусор
